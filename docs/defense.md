# Сценарий защиты

| Время | Что показать и объяснить |
| --- | --- |
| 0:00–0:50 | На примере конспекта объяснить, почему одна заметка получает два тега — «учёба» и «планы». |
| 0:50–2:10 | Создать запись, добавить текст и два тега, сохранить. Ещё раз открыть запись и изменить заголовок. |
| 2:10–3:10 | Выбрать тег. Ввести слово из текста. Показать выдачу без совпадений и сброс условий. |
| 3:10–4:10 | Закрыть приложение, открыть снова и найти сохранённую запись. Переключить светлую и тёмную темы. |
| 4:10–5:10 | В настройках сохранить блокнот в Markdown. Открыть полученный файл в текстовом редакторе. |
| 5:10–6:10 | Показать классы ViewModel, базу Room и юнит-тесты для поиска и экспорта. |
| 6:10–7:00 | Показать отмену удаления и подтверждение. Кратко объяснить, как проверялись сценарии. |
| 7:00–10:00 | Ответить на вопросы. |

**Почему Room?** Записи сохраняются при завершении процесса. Схему и запросы проверяет компилятор, а запись и перечитывание списка выполняются в транзакции.

**Как работают теги?** Ввод разбивается по запятым и переносам строк, убираются начальные решётки и лишние пробелы. Метки приводятся к нижнему регистру, повторы удаляются. Для личного блокнота они хранятся в одной колонке.

**Почему для экспорта не запрашивается доступ ко всем файлам?** Пользователь выбирает конкретный документ в системном диалоге. Android передаёт приложению URI с разрешением на запись.

**Что изменится при росте базы?** Сейчас поиск по небольшому блокноту выполняется в памяти. Для больших коллекций можно добавить таблицу связей тегов, полнотекстовый индекс SQLite и постраничную загрузку.
